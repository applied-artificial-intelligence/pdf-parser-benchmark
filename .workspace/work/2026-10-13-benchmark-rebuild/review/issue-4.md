# Issue 4: Establish task scoring that detects wrong associations

Requirement: Depends on Issue 3. Specify one downstream extractor over actual parser Markdown/text and one independent grader over its extracted fields/records. Keep extraction blind to all source/metadata/document-ID answer lookups; persist predictions before grading. Version and freeze normalization, required fields, row matching, extra/missing row penalties and all-fields/all-records document success. Test semantic correctness separately from edit similarity/chrF++. Reuse a pinned established record metric only if its input semantics match; do not implement a new generic TableRecordMatch framework to satisfy this one invoice task. Use exact multiset matching of complete displayed-column records, preserving duplicates, currency markers, units and Decimal values. Do not repair wrong associations to maximize a score. Initial development IDs are invoice_001 through invoice_006, the first observed example of each source template/complexity cell, plus smoke fixtures. Freeze the extractor before scoring; later changes version the protocol and require comparable regrading. These retained inputs are not an unseen test set.
