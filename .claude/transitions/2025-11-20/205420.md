## Recent Decisions

### 1. Use Content-Aware TEDS
**Rationale**: Structure-only TEDS (`teds_score`) was too lenient - scored 1.0 for tables with correct row/column count but missing cell content. Switched to `teds_score_with_content` which includes cell text in tree labels.

**Impact**: More discriminative scores (0.89-0.95 vs 1.0), better reflects actual table quality.

### 2. OmniDocBench Integration Strategy
**Decision**: Start with **Dual Evaluation** (Phase 1) rather than full integration.

**Rationale**:
- No information loss (both evaluation methods preserved)
- Research value: Compare how different evaluation frameworks rank parsers
- Low effort (~1 day)
- Can inform future integration decisions

**Alternative rejected**: Convert OmniDocBench JSON to markdown - would lose spatial/polygon annotations, formula LaTeX, table HTML ground truth.

### 3. Defensive Persistence Layer
**Decision**: Handle None values gracefully in `_serialize_metrics()` even though metrics should always return float/NaN.

**Rationale**: `math.isnan(None)` raises TypeError. While metrics shouldn't return None, defensive coding prevents mysterious serialization failures.

### TEDS Deep Dive
**Structure-only TEDS** (`teds_score`):
- Compares: rows, columns, cell positions, colspan/rowspan
- Ignores: cell text content
- Result: `<th>Sales Data</th>` vs `<th></th>` → 1.0 (structure identical)

**Content-aware TEDS** (`teds_score_with_content`):
- Compares: structure + cell text (includes content in tree node labels)
- Result: Same comparison → 0.947 (penalizes empty cell)
- Implementation: Line 248 in `teds.py` - `label = f"{label}{span_str}:{content}"`
