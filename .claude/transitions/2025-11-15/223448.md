## Recent Decisions

### LaTeX Normalization Approach
- **Decision**: Conservative normalization by default, aggressive mode optional
- **Rationale**: Preserves LaTeX semantics while allowing flexibility
- **Impact**: Users can choose strictness level for their use case
- Example: `normalize_latex(text, aggressive=True)` for redundant brace removal

### Space Handling in LaTeX
- **Decision**: Keep spaces after LaTeX commands (e.g., `\in ` vs `\in`)
- **Rationale**: Preserves LaTeX semantics - some commands need trailing space
- **Impact**: `x \in R` ≠ `x\in R` after normalization (intentional)
- **Alternative considered**: Aggressive space removal rejected (breaks valid LaTeX)

### Matching Algorithm Choice
- **Decision**: Greedy matching instead of optimal bipartite matching
- **Rationale**: Fast (O(m) average), deterministic, good enough for practice
- **Impact**: May not find optimal assignment in edge cases
- **Future enhancement**: Could add Hungarian algorithm option if needed

### Test Expectations
- **Decision**: Adjust test expectations to match normalization behavior
- **Rationale**: Tests should validate actual normalization, not ideal fantasy
- **Impact**: Tests reflect real-world LaTeX variations
- **Learning**: Initially had unrealistic expectations about space normalization
