## Lessons Learned

### What Worked

1. **Benchmark framework code** - Core infrastructure is solid
2. **Multiple parser integration** - Successfully integrated 4 parsers
3. **Ground truth lookup patterns** - Correctly handles different corpus structures
4. **GOV.UK ground truth generation** - Clean markdown from HTML (157-2053 lines)

### What Failed

1. **SEC HTML→Markdown** - Both custom converter and markdownify produce poor quality
2. **arXiv scope** - Wasted time on academic papers (not business documents)
3. **GOV.UK PDF downloads** - Downloaded wrong documents (factsheets vs reports)
4. **Data validation** - Should have tested quality BEFORE regenerating all 54 files
5. **Benchmark runtime** - 16-hour execution time is absurd for iteration

### Critical Insight

**HTML-as-ground-truth approach may be fundamentally flawed:**

HTML and PDF are semantically different:
- HTML: Structured markup (headings, paragraphs, tables)
- PDF: Positioned glyphs (x,y coordinates, fonts, styles)

Text extraction from PDF:
- Reading order often differs from HTML
- Tables extracted as space-separated text
- Multi-column layouts problematic
- Whitespace handling completely different

**Question**: Can we ever get >80% similarity comparing HTML→Markdown to PDF-extracted text? Or are we measuring the wrong thing?
