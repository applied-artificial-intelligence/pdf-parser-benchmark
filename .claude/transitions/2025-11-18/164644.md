## Recent Decisions

### 1. ar5iv HTML NOT suitable for ground truth
**Problem**: ar5iv uses LaTeXML semantic HTML, incompatible with PDF parser visual output
- Pandoc artifacts: `::: divs`, CSS classes, table wrappers
- Format differences: YAML frontmatter vs body text
- **Decision**: Use LaTeX source → Markdown via Pandoc `--standalone` flag

### 2. Built LaTeX normalization system (automated)
**Problem**: User rejected manual equation comparison, needed automation
- **Solution**: `latex_normalizer.py` with semantic equivalence rules
- Normalizes: bold commands, fractions, delimiters, whitespace, operators
- **Limitation**: 90% effective, misses edge cases like `\operatorname`, `\bigtriangleup` vs `\triangle`

### 3. Discovered evaluation methodology is flawed
**Key insight**: 20.2% score doesn't mean Marker is bad:

**Issue A - Equation splitting**:
- LaTeX source: `\begin{aligned}` = 1 multi-line equation
- PDF extraction: Marker sees 3 separate equation boxes = 3 equations
- Result: 79 found vs 59 expected (33% "over-extraction")
- **Both are correct** for their respective domains

**Issue B - Structural mismatch**:
- Ground truth: Abstract in YAML frontmatter (lines 1-9)
- Marker: Abstract in body text
- Result: All subsequent text offset, destroying similarity
- **Both are valid** Markdown, just different conventions

**Issue C - Reference formatting**:
- Ground truth: `Eq.[\[Eq1\]](#Eq1){reference-type="eqref"}`
- Marker: `Eq.(1)` with `<span id="page-0-0"></span>`
- **Fundamentally incompatible** - will never match

### 4. Marker output is actually excellent
**Evidence from manual inspection**:
- ✅ All 79 equations cleanly formatted, valid LaTeX
- ✅ Perfect `$$...$$` syntax, fully renderable
- ✅ Structure preserved: sections, theorems, proofs
- ✅ 57.5% inline math match rate (good for complexity)
- ✅ No corruption, no missing pages
