### Key Discovery: Marker+Ollama Integration Is Broken

**Problem**: Marker's `--llm_service marker.services.ollama.OllamaService` flag alone does NOT enable LLM usage.

**Root Cause Chain**:
1. **Missing flag**: Must also pass `--use_llm` to actually invoke LLM processors
2. **500 Server Error**: When `--use_llm` is enabled, Ollama returns HTTP 500
3. **Structured output issue**: Marker sends JSON schema via `format` parameter + images
4. **Vision model incompatibility**: llama3.2-vision doesn't support structured output with images

**Evidence**:
- Comprehensive benchmark: marker and marker_ollama both got **73.79%** (identical)
- Output files are byte-for-byte identical
- Ollama server logs show ZERO generation requests (without --use_llm)
- With --use_llm: Ollama receives request but returns 500 Internal Server Error
- Processing time: <1s (should be 6-7s if using LLM)

## Technical Details

### Why Marker Requires Vision Models

Marker's LLM integration works by:
1. Identifying complex regions (tables, equations, etc.)
2. Cropping those regions from PDF page **images**
3. Sending cropped images to vision LLM
4. Asking "what's in this table/equation?"

**This requires a vision model** - text-only models can't work because Marker sends actual images, not text.

### Marker's LLM Configuration

**Required flags**:
```bash
uv run marker_single document.pdf \
  --llm_service marker.services.ollama.OllamaService \
  --use_llm  # THIS FLAG IS CRITICAL - without it, LLM is never called
```

**Individual processor flags** (alternative to global `--use_llm`):
- `--LLMTableProcessor_use_llm`
- `--LLMSectionHeaderProcessor_use_llm`
- `--LLMComplexRegionProcessor_use_llm`
- etc.

### Ollama Service Implementation Issues

**Location**: `.venv/lib/python3.13/site-packages/marker/services/ollama.py`

**Problem line 52**:
```python
payload = {
    "model": self.ollama_model,
    "prompt": prompt,
    "stream": False,
    "format": format_schema,  # ← Structured output via JSON schema
    "images": image_bytes,     # ← Images for vision model
}
```

**Issue**: Combining `format` (structured output) + `images` (vision input) causes 500 error with llama3.2-vision.

### Ollama Server Behavior

**Text-only with structured output**: ✅ Works
```bash
curl -X POST http://localhost:11434/api/generate \
  -d '{"model": "llama3.2-vision", "prompt": "What is 2+2?",
       "format": {"type": "object", "properties": {"answer": {"type": "string"}}}}'
# Returns: {"answer": "4"}
```

**Images without structured output**: ✅ Probably works (not tested)

**Images + structured output**: ❌ 500 Internal Server Error
