## Completed Tasks

### 1. Diagnosed CUDA OOM Issue
- Previous session incorrectly attributed 127 failures to "missing document IDs"
- Actual cause: `torch.OutOfMemoryError: CUDA out of memory`
- Each marker instance uses ~3GB VRAM, 8 workers = ~24GB, exceeding GPU capacity (23.55 GiB)
- **Lesson learned**: Always consider GPU resource constraints for CUDA-heavy parsers

### 2. Fixed and Restarted Marker Benchmark
- Deleted old checkpoint and results files
- Re-ran with explicit `--workers 1` CLI flag (config file setting was ignored)
- Command: `nohup uv run pdfbench run benchmarks/marker_gap_fill.yaml -o results/marker_gap_fill.json --workers 1 > /tmp/marker_gap_single.log 2>&1 &`

## Key Learning

**GPU-heavy parsers like marker require explicit `--workers 1` on CLI** - the benchmark runner's auto-detection (8 workers) ignores the YAML config's `parallel_workers` setting. This caused CUDA OOM when multiple marker instances each tried to allocate ~3GB VRAM.
