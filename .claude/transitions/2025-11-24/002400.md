## Session Summary

This session diagnosed and fixed two critical benchmark issues that were producing misleading results.

### Issues Fixed

#### 1. Azure F0 Tier 2-Page Limit
- **Symptom**: Azure only returning 2 pages for multi-page documents
- **Diagnosis**: Tested cuad_007.pdf (11 pages) - Azure returned only 1,252 chars instead of 16,720
- **Root cause**: Azure resource on F0 (Free) tier with 2-page limit
- **Fix**: User upgraded to S0 (Standard) tier in Azure Portal
- **Verification**: After upgrade, Azure returned all 11 pages (16,517 chars)

#### 2. Invoice Ground Truth Format Mismatch
- **Symptom**: All parsers scored 30-44% on invoices despite correct text extraction
- **Diagnosis**: Ground truth extracted from DOCX had markdown tables (`| col | col |`)
- **Root cause**: `builders/generate_invoice_corpus.py` used DOCX table format
- **Fix**: Regenerated ground truth from PDF using `pymupdf.get_text()` (plain text)
- **Result**: Invoice scores jumped from ~35% to ~70-90%

### Technical Details for Invoice Ground Truth Fix
The old ground truth was generated by `builders/generate_invoice_corpus.py` which extracted tables from DOCX as:
```
Description | Quantity | Unit | Unit Price | Amount
Enterprise Plan | 45.87 | subscription | $71,834.13 | $3,295,031.54
```

PDF parsers extract the same content as plain text:
```
Description
Quantity
Unit
Unit Price
Amount
Enterprise Plan
45.87
subscription
$71,834.13
$3,295,031.54
```

The fix used `pymupdf.get_text()` to regenerate ground truth from the actual PDFs, matching what parsers extract.
