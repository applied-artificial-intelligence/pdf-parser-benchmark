## Session Summary

This session investigated why Google/Databricks had poor benchmark scores and implemented format-agnostic metrics to address a fundamental methodology flaw.

### Key Discovery: Format Sensitivity Bias

The benchmark was penalizing parsers for output format differences, not extraction quality:

| Parser | Raw Score | Format-Agnostic | Token Recall |
|--------|-----------|-----------------|--------------|
| Azure | 93% | 100% | 100% |
| Databricks | **48%** | **92%** | **100%** |
| Google | 46% | 77% | 96% |

**Root causes:**
- **Databricks** outputs HTML tables (`<table><tr><td>`) - massively penalized
- **Google** adds markdown headers (`# INVOICE`) and breaks numbers (`45. 87`)
- **Azure** outputs plain text matching pymupdf ground truth - unfair advantage

### Implementation

**New normalization functions** (`pdf_bench/utils/normalization.py`):
- `strip_markdown()` - Removes `#` headers, `**bold**`, `*italic*`, links
- `strip_html()` - Removes all HTML tags
- `fix_number_spacing()` - Fixes `45. 87` → `45.87`
- Added `strip_formatting=True` parameter to `normalize_text()`

**New metrics** (`pdf_bench/metrics/edit_distance.py`):
- `edit_similarity_normalized()` - Format-agnostic edit similarity
- `token_recall()` - Content extraction completeness (ignores order/formatting)

**Documentation** (`docs/RESULTS.md`):
- Added "Methodology and Limitations" section
- Explains format sensitivity issue with concrete example
- Recommendations for interpreting results

### Re-running Benchmarks

**No re-parsing needed.** The benchmark stores parsed output in cache (`.cache/{parser}/`). To compute format-agnostic scores:

1. Load existing results from `results/commercial_200docs.checkpoint.json`
2. For each result, load cached parser output and ground truth
3. Compute new metrics using `edit_similarity_normalized()` and `token_recall()`

The cache uses hash-based naming: `{parser}-{version}-{file_hash}.md`
