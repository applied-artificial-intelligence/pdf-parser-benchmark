## Recent Decisions

### Parser Integration Strategy
- **Decision**: Prioritize pdfplumber before Marker for implementation
- **Rationale**: Simpler integration (pure Python), faster completion, demonstrates progress
- **Impact**: pdfplumber completed (TASK-086), Marker installation complete (TASK-029), ready for Marker adapter (TASK-030)

### Nougat Cancellation
- **Decision**: Cancel Nougat integration (TASK-031, TASK-032)
- **Rationale**: Redundant with Marker (both Meta, both ML-based), heavy GPU requirements, slow inference
- **Impact**: Freed 6 hours, simplified parser lineup, Marker provides better coverage

### Databricks Integration
- **Decision**: Add as Tier 2 (optional) parser
- **Rationale**: User-requested, represents unique "platform-integrated" approach, new (late 2024)
- **Requirements**: Databricks workspace, Runtime 17.1+, Mosaic AI access
- **Impact**: TASK-087 added (6h, Phase 9, medium priority)

### pdfplumber Table Format
- **Decision**: Use GitHub Flavored Markdown (GFM) for table output
- **Rationale**: Simple, human-readable, widely supported, consistent with benchmark goals
- **Alternative considered**: HTML tables (rejected for complexity)
- **Impact**: Clean, consistent table representation across parsers

### Marker Dependency Group
- **Decision**: Create separate `ml-parsers` optional dependency group
- **Rationale**: GPU requirements (PyTorch, torchvision) are heavy, not needed for basic parsers
- **Impact**: Users can install basic parsers without GPU dependencies, flexibility for different environments
