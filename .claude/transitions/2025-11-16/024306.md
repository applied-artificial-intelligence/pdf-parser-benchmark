## Recent Decisions

### 1. Metadata Schema Standardization (Critical!)
**Decision**: Migrated all corpus metadata to standard DocumentMetadata schema instead of creating workarounds
**Rationale**: Avoid tech debt from day one, ensure clean foundation
**Impact**: All 8 synthetic corpus files now use doc_id, corpus, domain fields consistently
**Files Changed**: corpus/synthetic/*.yaml (8 files migrated)

### 2. File Stem vs Doc ID for Path Resolution
**Decision**: Use file stem (e.g., "01_basic") not doc_id (e.g., "syn-basic-001") for discovering PDF/MD files
**Rationale**: Actual files are named by stem, not doc_id
**Implementation**: `file_stem = metadata_path.stem` in discover_documents()

### 3. Parser Registry Pattern
**Decision**: Explicit dict mapping parser IDs to classes (PARSER_REGISTRY)
**Rationale**: Type-safe, extensible, no import magic
**Benefit**: Clear registration, easy to add new parsers

### 4. Separate LoadedConfig from BenchmarkConfig
**Decision**: Two classes - BenchmarkConfig (serializable) vs LoadedConfig (runtime-ready with instances)
**Rationale**: Separation of concerns
**Benefit**: Config is YAML-serializable, LoadedConfig has instantiated parsers

### 5. Benchmark Config Path Resolution
**Decision**: Use ../corpus for corpus_dir in benchmark configs (not corpus)
**Rationale**: Configs are in benchmarks/ directory, corpus is at project root
**Impact**: All 4 example configs updated to use relative paths correctly
