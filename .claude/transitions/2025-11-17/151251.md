## Technical Notes

### Cost Tracking Implementation
Both commercial parsers track costs at three levels:
1. **Per-parse**: `parser.last_parsing_cost` (float)
2. **Session total**: `parser.get_total_cost()` (float)
3. **Aggregated reporting**: `CostReport` class with multi-parser support

### Cache Integration
Commercial parsers fully integrated with caching system:
- Cache key includes parser name + version
- Cache hit → cost = $0.00 (no API call)
- Cache miss → API call + cost tracking + cache storage

### Error Handling Pattern
Comprehensive error handling for both parsers:
- **AWS**: ThrottlingException, InvalidParameterException, ProvisionedThroughputExceededException
- **Azure**: HttpResponseError, ResourceNotFoundError, ServiceRequestError
- All errors converted to informative RuntimeError or ValueError

### Security Implementation
- **Environment variables**: Primary credential method (development)
- **IAM roles**: Recommended for production (AWS)
- **Managed Identity**: Recommended for Azure production
- **No hardcoded credentials**: All parsers validate env vars or constructor args
- **Security warnings**: README emphasizes credential rotation, least-privilege IAM
