## Recent Decisions

### Architecture Decisions

1. **LaTeX Extractor Heuristics** (TASK-061)
   - Decision: Use 3-tier heuristic system for main .tex identification
   - Rationale: arXiv tarballs have inconsistent structures; multi-tier approach ensures robust identification
   - Impact: 100% success rate on test cases

2. **LaTeXML Wrapper Design** (TASK-062)
   - Decision: Wrapper should work gracefully even when LaTeXML not installed
   - Rationale: Enables testing without LaTeXML dependency, better error messages for users
   - Implementation: Mock-based unit tests, clear installation instructions in exceptions
   - Impact: All tests runnable without LaTeXML installation

3. **Math Preservation Strategy** (TASK-063)
   - Decision: Preserve LaTeX math as-is in Markdown (`$...$` and `$$...$$`)
   - Rationale: LaTeX is the ground truth for mathematical content; conversion would lose fidelity
   - Implementation: Extract LaTeX from `<annotation encoding="application/x-tex">` tags
   - Impact: Perfect math fidelity for benchmarking

4. **Table Conversion Strategy** (TASK-063)
   - Decision: GFM for simple tables, HTML fallback for complex
   - Rationale: Balance readability (GFM) with fidelity (HTML for merged cells, nested tables)
   - Criteria: Simple = uniform columns, no rowspan/colspan, no nested tables
   - Impact: Readable output for simple tables, accurate representation for complex tables

### Code Patterns Established

1. **Error Handling Pattern**:
   ```python
   class ToolNameError(Exception):
       """Base exception for tool-related errors."""
       pass

   class ToolNameNotInstalledError(ToolNameError):
       """Raised when tool is not installed."""
       pass

   class ToolNameConversionError(ToolNameError):
       """Raised when conversion fails."""
       pass
   ```

2. **Subprocess Wrapper Pattern**:
   - Use `subprocess.run()` with `capture_output=True`, `text=True`
   - Always include `timeout` parameter
   - Use `check=False` to handle errors manually
   - Return dict with `success`, `returncode`, `stdout`, `stderr`, `error`

3. **Test Structure Pattern**:
   - Fixtures for temporary directories (`temp_dir`)
   - Fixtures for sample input files
   - Mock external dependencies (LaTeXML, subprocess calls)
   - Test both success and failure paths
   - Test edge cases (empty input, malformed input, missing files)
